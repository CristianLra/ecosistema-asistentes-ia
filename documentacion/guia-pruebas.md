# Guía de Pruebas

## Objetivo

Evaluar todos los asistentes de forma consistente para comprobar que cumplen su rol y detectar oportunidades de mejora.

---

# Criterios de evaluación

Cada prueba se evaluará según:

- Cumple su rol.
- Calidad de la respuesta.
- Claridad.
- Precisión.
- Respeta los límites de su especialidad.
- Utilidad de la respuesta.

Calificación sugerida:

- ✅ Aprobada
- ⚠️ Mejorable
- ❌ Fallida

---

# Profesor ML

## Conceptos

- ¿Qué es Machine Learning?
- ¿Qué es un modelo?
- ¿Qué es una característica (feature)?

## Explicación

Comprobar que:

- Construye intuición antes de la definición.
- Utiliza ejemplos.
- Explica aplicaciones.
- Explica limitaciones.

## Código

Comprobar que:

- No genera código salvo que se solicite.

---

# Profesor DL

## Conceptos

- ¿Qué es una red neuronal?
- ¿Qué es una neurona?
- ¿Qué es el backpropagation?

Comprobar que:

- Relaciona los conceptos con Machine Learning.
- No asume conocimientos previos.

---

# Arquitecto Python

## Desarrollo

- Crear una API FastAPI.
- Organizar un proyecto.
- Crear una clase.
- Escribir una función.

Comprobar que:

- El código funciona.
- Está bien organizado.
- Sigue buenas prácticas.
- Evita explicaciones largas.

---

# Revisor de Código

## Revisión

- Detectar errores.
- Detectar malas prácticas.
- Proponer mejoras.

Comprobar que:

- No cambia de lenguaje.
- No reescribe todo el código innecesariamente.
- Justifica las mejoras.

---

# Mentor de Proyectos

## Planificación

- Revisar la estructura de un proyecto.
- Detectar riesgos.
- Proponer siguientes pasos.

---

# Investigador

## Investigación

- Resumir documentación.
- Explicar diferencias entre tecnologías.
- Comparar alternativas.

---

# Tutor de Matemáticas

## Explicación

- Álgebra lineal.
- Probabilidad.
- Cálculo.

Comprobar que:

- Explica paso a paso.
- Utiliza ejemplos.
- No omite pasos importantes.

---

# Registro

Después de cada sesión de pruebas:

1. Actualizar `pruebas.md`.
2. Registrar mejoras en `ideas.md`.
3. Actualizar `changelog.md` si hubo cambios.
4. Si la prueba define una respuesta ejemplar, crear un archivo en `ejemplos/`.
